# 食品饮料产业链图谱三种抽取方式对比分析

> 版本说明：**V1.0** 为自研 Agent 不参考申万分类的版本，**V2.0** 为自研 Agent 参考申万分类的版本；另以 Claude Code 直接抽取版本作为对照。  
> 对比范围：比较产业链主图的 L1 骨架、L0–L4 分类层级、节点质量与证据完整性；不涉及公司节点和额外关系附件。  

## 一、核心结论

**V2.0 最适合作为正式图谱基线。**

其优势不在于节点最多，而在于：

1. **L1 骨架更精炼**：用 7 个一级环节覆盖上游原辅料、中游核心品类制造和下游流通消费，领导查看时主线更清楚。
2. **层级更有分析深度**：形成完整 L0–L4 结构，并有 24 个 L4 节点；Claude Code 版止于 L3。
3. **证据可追溯**：自研 Agent 对节点来源和证据记录进行统一管理；Claude Code 版的证据覆盖不全面，无法确保节点级可追溯。
4. **质量可控**：V1.0 和 V2.0 均通过项目硬规则校验；Claude Code 版尚未满足正式交付所需的来源完整性要求。

V1.0 同样具备完整证据和合格格式，但 L1 同时放入原料、制造、设备、物流和渠道，分类轴相对分散。对比显示，分类参考的主要价值是帮助 Agent 对核心品类重新聚类、压缩骨架，而不是机械复制外部目录。

## 三、L1 骨架对比

### 1. V2.0：骨架最简洁

共 7 个 L1：

- 上游：食品原料、辅料与包材供应链
- 中游：酒类制造、乳品与非酒精饮料制造、调味发酵品制造、休闲食品与烘焙制造、肉制品与预制便捷食品制造
- 下游：食品饮料流通与消费渠道

这一结构把上游和下游各自收敛为一个入口，中游再按具有投研辨识度的核心品类展开。一级页面容易读懂，也为后续分支扩展保留了清晰边界。

### 2. V1.0：产业链完整，但分类轴较散

共 9 个 L1：

- 上游：农产品原料、食品添加剂与配料、包装材料
- 中游：食品制造、饮料制造、酒类制造
- 支持：生产设备与品控、冷链物流与仓储
- 下游：流通渠道与零售终端

优点是传统“原料—制造—支持—渠道”链条完整；不足是 L1 同时混合了供给对象、制造大类和支持职能。特别是“食品制造”范围较宽，导致大量具体品类集中在 L2，一级骨架的行业辨识度弱于 V2.0。

### 3. Claude Code 直接抽取：表面覆盖更宽，但一级层级偏重

共 11 个 L1：3 个上游、6 个中游、2 个下游。其将“农产品与畜牧原料”“食品添加剂与辅料”“食品包装材料”，以及酒类、乳制品、饮料、调味品、休闲食品、肉制品等全部放在 L1。

这种方式适合快速形成初稿，但 L1 承载内容较多，主骨架更像“一次性完整目录”。后续新增或调整品类时，较容易继续横向增加一级节点，缺少稳定的骨架收敛机制。

## 四、直观例子

### 例 1：同样是调味品，V2.0 形成更完整的分类路径

- V2.0：`食品饮料行业 → 调味发酵品制造 → 复合调味料 → 中式复合调味料 → 火锅底料`
- V1.0：`食品饮料行业 → 食品制造 → 调味品制造 → 复合调味料 → 火锅底料`
- Claude Code 版：主要展开到 L3，没有形成 L4 层级。

V2.0 在“复合调味料”下继续区分“中式复合调味料”，既保留行业主类，也能落到“火锅底料”这一具体赛道，层次更适合分析和展示。

### 例 2：V2.0 的 L4 不只集中在单一分支

其 L4 同时覆盖中游产品和上游材料，例如：

- `酒类制造 → 啤酒 → 精酿啤酒 → 鲜啤与原浆啤酒`
- `乳品与非酒精饮料制造 → 乳制品制造 → 常温液态奶 → 常温白奶`
- `食品原料、辅料与包材供应链 → 包装材料 → 塑料包装 → PET 饮料瓶`
- `食品原料、辅料与包材供应链 → 食品添加剂与配料 → 甜味剂 → 糖醇与天然代糖`

这说明 L4 是在关键分支中按业务需要下钻，而不是为了增加节点数量机械加深。

### 例 3：230 个节点不代表可直接交付

Claude Code 版有 230 个节点，数量明显更多，但：

- 156 个节点集中在 L3，整体呈现“宽而平”的结构；
- 没有 L4 节点；
- 节点级来源和证据覆盖不全面；
- 当前结果无法确保每个分类节点都能回溯到可靠依据；
- 尚未通过项目对来源完整性的交付校验。

因此，它更适合作为候选概念召回或头脑风暴结果，不能直接作为可审计的正式产业链图谱。

## 五、为什么自研 Agent 效果更好

| 能力 | 自研 Agent | Claude Code 直接抽取 |
|---|---|---|
| 构建方式 | 先形成并评估 L1 骨架，再逐分支扩展 | 直接生成整图 |
| 分类控制 | 可用申万分类辅助召回，并允许重命名、合并、拆分和舍弃 | 主要依赖单次生成时的模型判断 |
| 层级控制 | 明确要求 L0–L4，并按分支检查深度与覆盖 | 当前结果集中在 L1–L3 |
| 证据要求 | 节点必须绑定 URL 与证据 ID | 当前证据覆盖不全面，无法确保节点级可追溯 |
| 质量保障 | 标准化、硬规则校验、必要时格式修复 | 当前结果未经过同等交付校验 |
| 适用场景 | 正式图谱构建与持续维护 | 快速初稿、候选概念补充 |

## 六、汇报建议

建议将三种方式定位为：

1. **V2.0：正式基线版本。** 骨架清晰、层级深入、证据完整，综合效果最佳。
2. **V1.0：消融对照版本。** 证明即使没有外部分级参考，自研流程仍能产出合格图谱；同时也说明分类参考有助于收敛 L1 骨架。
3. **Claude Code 直接抽取：快速初稿版本。** 广度较高，可用于补充候选节点，但缺少证据与质量控制，不能用节点数替代正式图谱质量。

一句话总结：**Claude Code 可以快速“列出很多内容”，自研 Agent 则能够把内容组织成结构清晰、层级可控、证据可追溯的产业链图谱。**

## 七、客观限制

V2.0 目前有 136 个节点，部分分支仍可继续扩展；Claude Code 版的一些细分类目也具有候选价值。后续可将其作为召回补充，但新增节点仍应经过自研 Agent 的分类归位、证据补全和硬规则校验，避免为了追求数量破坏骨架稳定性。
