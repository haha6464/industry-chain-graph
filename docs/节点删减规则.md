# 产业链图谱构建中的节点删减规则

适用范围：从一级骨架构建、分支扩展、最终校验、L2 关系构建到公司挂载及交付；**不包含增量更新流程**。

## 一览

| 阶段 | 是否会删产业链节点 | 规则 |
| --- | --- | --- |
| 一级骨架 / 分支质量修正 | 可能 | 删除、合并或上收不符合投研产业链分类口径的节点。 |
| 分支最低规模校验 | 不会 | 分支不达标时不生成候选图谱，不会静默删掉该分支。 |
| 图谱标准化 | 会 | 删除“非根节点下唯一的末级分类子节点”这一冗余层。 |
| 最终硬规则 / 格式修复 | 不会 | 只修工程格式；不因覆盖度或粒度删除节点。 |
| L2 上下游关系构建 | 不会 | 只新增或清理 L2 关系附件，不删主图节点。 |
| 公司挂载后的覆盖裁剪 | 会 | 先删除无法挂载任何可见公司的产业链节点，再次压缩新产生的唯一末级分类子节点。 |
| CSV / 离线 HTML 导出 | 不会 | 只读取正式图谱和公司挂载结果。 |

## 1. 一级骨架与分支质量修正

质量评估未通过时，分类修正 Agent 可以删除、合并或上收以下低价值节点：

- 公司、股票代码、财务指标等个股信息；
- 平台能力、泛咨询、SaaS/解决方案、体系/网络等泛化概念；
- 新闻、政策标题、市场趋势等非稳定产业分类；
- 单个生产动作或连续工艺步骤。

优先将其改为可挂载公司的稳定分类，例如产品、材料、设备、渠道或应用场景。修正不得大规模重写图谱；一级骨架修正后仍必须保留至少一个上游 L1 和一个下游 L1。

## 2. 分支最低规模：阻断，不删分支

每个 L1 分支至少要形成 8 个 L2-L4 节点，并且所有子节点必须沿 `parent_id` 归属于该 L1。

不达标、扩展失败或归属错误时，会保留中间产物和错误记录，**不生成校验前候选图谱**。这不是“删掉一个差分支后继续交付”。

## 3. 标准化时删除唯一末级子节点

图谱每次经过 `standardize_graph()` 时，执行确定性压缩：

> 非根节点 P 只有一个 `contains` 子节点 C；C 是 L2 或更深的叶子节点（没有任何 `contains` 子节点）时，删除 C 及其关联边。

目的：删除只有一层命名、没有分类信息增量的冗余叶子层。L0 根节点的唯一子节点不会因这条规则被删除。

## 4. 最终校验与 L2 关系阶段：不按质量删节点

- 最终硬规则校验中的格式修复仅处理字段、关系方向、缺失来源等工程问题；不因节点数量、覆盖广度或层级粒度新增、删除节点。
- L2 上下游关系阶段只处理 `l2_flow_relations.json` 中的关系和投影边；不会删除 `graph.json` 的节点。
- 同 ID 节点在合并时只合并来源等信息；异义 ID 冲突会报错。疑似同名节点只进入复核队列，不自动删除。

## 5. 公司挂载后的覆盖裁剪与二次唯一叶子压缩

仅在 L2 关系附件 ready、且公司挂载通过校验后执行。

1. 先只保留境内上市公司的有效直接挂载。
2. 保留每个直接挂载节点，以及它沿**分类隶属关系**向上的父节点（`parent_id` / `contains`）。
3. `upstream_downstream` 只是产业传导关系，不是聚合父子关系：L0-L1 为上下游的分支，公司最多聚合到 L1，不会聚合到 L0。
4. L0 根节点始终作为图谱结构保留。
5. 不在上述保留集合中的产业链节点及其主图边全部删除。

覆盖裁剪会改变分类树的子节点数量，因此裁剪完成后必须**再次**执行第 3 节的“唯一末级子节点”压缩，以删除本轮裁剪新产生的冗余层。若被删除的唯一子节点有公司直接挂载，先将该挂载上移到父节点，再删除子节点，保证公司证据不丢失。

## 6. 不属于节点删减的情况

- 节点数低于 120、L1 数量偏少、疑似同名或层级偏浅：只产生 warning / 复核意见，不自动删节点。
- 公司挂载格式修复可删除无效、重复或祖先-后代重复的**挂载记录**，不删除产业链节点。
- CSV 和离线 HTML 导出不再调用图谱标准化，不会因导出额外删节点。
